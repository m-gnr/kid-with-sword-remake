# Optimization plan

Start with a controlled baseline and sparse encoder profiling. Choose the first code change using base-M3 evidence. `DM_NVN_DISPATCH_OVERLAP` is the first reversible A/B to try after the baseline. Foliage is the first backport to assess if profiling places the implicated mesh work high in the ranking.

A settings-only comparison uses the current executable and archives. A chain change requires a new chain header, a matching full game shader set with its input stamp, a matching host and an offline pipeline archive if the experimental app uses one. Keep the experiment in a separate app path. Wait for approval before the full game rebuild or substantial renderer changes.

## Rebuild and resource scope

- Dispatch overlap and stage-by-stage scaling use runtime environment variables and require a fresh process for each setting. The clone reuses existing libraries and the bundled offline archive. Its apparent size is about 34 GiB. APFS cloning on the same volume shares the initial blocks. The per-run learned pipeline archive fixture is about 142 MiB before copy-on-write growth. The captured M3 frame used 7.7 GiB. Reserve at least 8 GiB per comparable capture, plus space for the Instruments trace.
- A native-store prototype can start with synthetic shader tests and an isolated one-key compile. Runtime comparison requires the complete matching M3 shader set, regenerated chain header, host, matching profile tables and a separate offline archive. Reuse extracted RomFS and rewritten modules if their inputs match. The present Mac build holds about 11 GiB of packed shader outputs, 13 GiB of compiler cache, 4 GiB of offline archive scratch, 5.8 GiB of app shader libraries and 3.2 GiB of bundled pipelines. These are reference sizes, and scratch use or compiler memory for the new chain remains unmeasured. Allow at least 40 GiB for a separate shader, archive and app-output workspace on the external APFS volume, plus trace space. Phase Two preflight found about 381 GiB free there.
- The baseline chain pins the translator files in `dmsh_chain.lock`. A local republish needs matching lock and header in the isolated build. Resolve how to reproduce that translator without uploading binaries before a source-only backport is published. After approval, run the upstream focused shared-store, Ampere and mesh tests, the chain check and applicable game regressions per the [developer loop](../agents/06-dev-loop.md#7-before-you-open-a-pull-request).

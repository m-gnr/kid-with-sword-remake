# Optimization plan

Start with a controlled baseline and sparse encoder profiling. Choose the first code change using base-M3 evidence. `DM_NVN_DISPATCH_OVERLAP` is the first reversible A/B to try after the baseline. Foliage is the first backport to assess if profiling places the implicated mesh work high in the ranking.

| Candidate | Expected benefit and evidence | Dependencies and effort | Correctness checks and status |
| --- | --- | --- | --- |
| Native subword threadgroup stores in [shader build](../../dm/gfx/tools/dmsh_build.py) and the translator | Less contention between lanes that write different bytes in one word. Phase One cites an expensive M3 Pro foliage pass. M3 savings are unavailable. | Verify upstream producer and postpass together. Medium integration effort plus a chain build and graphics validation. | Compare primitive count and indices, barriers, foliage and occlusion in color and depth. Test across lanes sharing a word and both byte and half-word writes. Assessment pending. |
| Texture residency in [NVN replay](../../dm/gfx/nvn/nvn_mtl.m) | Fewer redundant uploads and residency updates, or less memory pressure if the counters confirm churn. Phase One saw high footprint and an entry upload. | Establish allocation, upload and retirement timing first. Medium to high if backing lifetime changes. | Reload the scene and cross area boundaries. Check terrain, texture views, depth targets and reclaimed guest data. Investigation pending. |
| Independent NDSR and presentation scaling in [NVN replay](../../dm/gfx/nvn/nvn_mtl.m) | A scaler may cost less at the same sizes. Phase One found an unknown ending, so active-path verification comes first. | Same dimensions and matched screenshots. Low for runtime A/B, medium if chain recognition requires code changes. | Compare geometry edges, fine foliage, temporal shimmer, HUD and color. Keep the existing path where quality differs. Investigation pending. |
| Dispatch overlap in [NVN replay](../../dm/gfx/nvn/nvn_mtl.m) | Possible reduction in compute span. M4 Pro result was 27.1 → 24.9 ms per frame. M3 effect is unavailable. | Same app, `DM_NVN_DISPATCH_OVERLAP=0` vs `1`, one setting per launch. Low effort. | Confirm that the runtime honors the switch and review snapshots, foliage movement and transitions for ordering errors. A/B pending. |
| Pacing in [NVN replay](../../dm/gfx/nvn/nvn_mtl.m) and the [build-specific frame-step hooks](../../dm/games/0400486024DEC000/patches.py) | Fewer missed refreshes if display or acquire waits account for the slow frames. No timing attribution yet. | Presented timestamps, display intervals and a simulation-speed check. Medium to high if changes cross the guest/host boundary. | Record presented and discarded frames and time the same gameplay action. Investigation pending. |

A settings-only comparison uses the current executable and archives. A chain change requires a new chain header, a matching full game shader set with its input stamp, a matching host and an offline pipeline archive if the experimental app uses one. Keep the experiment in a separate app path. Wait for approval before the full game rebuild or substantial renderer changes.

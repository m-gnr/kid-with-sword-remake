# Phase Three technical report

## Base M4 investigation outcome

The [community evidence and source comparison](07-base-m4-investigation.md) identifies a base M4 / 24 GB run on nxnative `main` `75c1a8cf` plus four local PRs: **39.5 FPS outdoors and 45.2 FPS inside Link's house**, in Handheld mode. A later scripted run on the same named stack with a simulation patch reported **41.6 FPS outdoors uncapped**, at a 2560 × 1440 window drawable. The earlier same-save comparison was **34.7 → 45.2 FPS inside the house** across a stack of changes. We could not verify a matched 20 → 40–45 FPS comparison. The reports near 60 FPS include different hardware, settings or scenes. They do not validate 60 FPS in the village on a base M4.

The strongest individual base M4 A/B evidence is for lower submit CPU time and fewer long frames from [pool-table change notes](https://github.com/seedds/nxnative/pull/1489); median frame time did not change. Other plausible contributors include fewer depth-related pass splits and less pressure from texture and archive residency. The tested MetalFX, fullscreen and reduced-resolution settings did not explain a large uplift on the reported route. The real-time frame delta corrected game speed, and the measured HMMA improvement was for the title movie. The fork already has equivalents of several renderer and residency changes, as well as a different frame controller. A broad merge would retest fixes we already have and obscure what changed.

## What this means for base M3

The target stays **60 presented FPS in Docked, Normal, fullscreen**, with accurate game speed and visuals. The [controlled base M3 comparison](04-benchmarks.md#ordinary-dispatch-overlap-ab) is **20.52 → 20.87 presented FPS** with dispatch overlap and **35.26 → 33.97 ms** tagged GPU span p50. The median display interval stayed at 50 ms. The measured 3D size was already 854 × 480 despite a 2560 × 1440 game output and 3600 × 2025 drawable. At the baseline median, the GPU span alone exceeds the 16.67 ms target by 18.59 ms. Recovering one or two milliseconds or improving display cadence is useful, but no single examined patch closes that gap.

| Defer | Whole-fork merges, the private archive mapping hook, an extra frame-delta patch, title-only HMMA work, and the full sibling raw-read chain. | Revisit the individual mechanism only if a specific workload, compatibility gap or timing failure warrants it. |

For each trial, pin the executable hash, shader chain and input stamp, save/camera path, mode, cap, display refresh, render/output/drawable sizes, both scaler paths, pipeline archive location and cache warmth. Record physical footprint, GPU allocation and residency separately, along with swap deltas. Alternate at least three accepted timing runs per setting. Collect diagnostic captures outside the timing windows and track correctness through the same transitions, including terrain, water, foliage and game time.

This phase reviewed public reports and source only. It changed documentation; no host, profile or shader code changed, and no build, packaging run or new gameplay run was started. The full rebuild remains subject to approval. Any later code change needs the focused checks and applicable game regressions in the [developer loop](../agents/06-dev-loop.md#4-checking-a-change-on-every-game-scriptsregresspy).

Documentation validation: the new local links and anchors resolve. The repository-wide suite produced the same three failures before and after this change: existing broken relative links, a stale patch index and a stale symptom index.
